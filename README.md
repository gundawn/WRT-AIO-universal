OpenWrt All In One Universal Script (OAIOUS)

OpenWrt All In One Universal Script (OAIOUS) — AIO-скрипт для автоматической первоначальной подготовки роутера на OpenWrt.

Скрипт в одном запуске выполняет обновление списков пакетов и установленного ПО, устанавливает или обновляет русскую локализацию LuCI, настраивает часовой пояс и синхронизацию времени, предлагает выбрать Software или Hardware Flow Offloading, включает Packet Steering и Steering Flows 128, проверяет объём Flash-памяти, устанавливает фиксированную версию sing-box-extended 2.7.1 под архитектуру конкретного устройства, устанавливает или обновляет NetShift, а также создаёт задачи Cron для ежедневной перезагрузки и автоматического обновления пакетов.

Скрипт рассчитан не только на первичную установку, но и на повторный запуск: перед выполнением отдельных действий он проверяет, установлены ли необходимые компоненты и требуют ли они обновления.

⸻

🚀 Быстрая установка

Подключитесь к роутеру по SSH от имени root и выполните:

wget -O - https://raw.githubusercontent.com/gundawn/WRT-AIO-universal/main/install.sh | sh

После запуска скрипт автоматически определяет:

* версию OpenWrt;
* архитектуру устройства;
* пакетный менеджер apk или opkg;
* архитектуру пакетов;
* необходимое расширение пакета (.apk или .ipk);
* наличие уже установленных компонентов;
* наличие доступных обновлений;
* наличие русской локализации;
* текущие настройки сетевого ускорения;
* общий объём файловой системы /overlay;
* подходящий пакет sing-box-extended для конкретной архитектуры;
* необходимость установки или обновления NetShift.

После запуска следуйте инструкциям, отображаемым в терминале.

⸻

⚙️ Что делает скрипт

1. 📦 Обновление списков пакетов

Сначала скрипт обновляет списки пакетов штатным пакетным менеджером системы:

* apk для новых версий OpenWrt;
* opkg для систем, использующих старый пакетный менеджер.

Результат отображается в итоговом отчёте.

⸻

2. 🔄 Обновление установленных пакетов

После обновления списков выполняется обновление доступных пакетов.

Для apk используется:

apk upgrade --available

Для opkg скрипт получает список доступных обновлений и обновляет пакеты по отдельности.

Таким образом, обновление системы выполняется одной командой вместе с остальными этапами AIO-установки.

⸻

3. 🇷🇺 Русская локализация

Скрипт проверяет пакет:

luci-i18n-base-ru

Возможны три варианта:

* пакет отсутствует → устанавливается;
* пакет установлен, но доступно обновление → обновляется;
* актуальная версия уже установлена → ничего не изменяется.

После проверки результат отображается в итоговом отчёте.

⸻

🕐 4. Часовой пояс и синхронизация времени

Скрипт проверяет текущие параметры OpenWrt и устанавливает:

Asia/Yekaterinburg
GMT+5

Используются параметры:

zonename = Asia/Yekaterinburg
timezone = +05

После этого скрипт проверяет наличие:

/etc/init.d/sysntpd

Если сервис присутствует, он включается и перезапускается для синхронизации времени.

В результате проверяется не только значение часового пояса, но и успешный запуск sysntpd.

⸻

⚡ 5. Сетевое ускорение

Скрипт автоматически проверяет существующие настройки сетевого ускорения.

Если Offloading ещё не включён, пользователю предлагается выбрать один из вариантов:

1) Software Flow Offloading
2) Hardware Flow Offloading

Software Flow Offloading

При выборе 1 устанавливается:

flow_offloading = 1
flow_offloading_hw = 0

Hardware Flow Offloading

При выборе 2 устанавливается:

flow_offloading = 0
flow_offloading_hw = 1

Packet Steering

Дополнительно скрипт включает:

packet_steering = 2

что соответствует использованию всех доступных CPU для Packet Steering.

Steering Flows

Также устанавливается:

steering_flows = 128

Если необходимые значения уже установлены, повторно изменять их не требуется.

После изменения конфигурация сохраняется через UCI, перезагружается Firewall/Packet Steering, а затем значения повторно считываются и проверяются.

В итоговом отчёте сетевое ускорение получает отдельный статус.

⸻

💾 6. Проверка Flash-памяти

Перед установкой тяжёлых компонентов скрипт определяет общий объём файловой системы:

/overlay

Если определить /overlay невозможно, используется корневая файловая система / как запасной вариант.

Минимальный порог, установленный в скрипте:

50 MB

Если Flash ≥ 50 MB

Разрешается обработка:

* sing-box-extended;
* NetShift.

Если Flash < 50 MB

Скрипт не прекращает выполнение.

Он продолжает остальные этапы:

* обновление списков пакетов;
* обновление пакетов;
* русская локализация;
* часовой пояс;
* синхронизация времени;
* сетевое ускорение;
* Cron.

При этом установка/обработка:

* sing-box-extended;
* NetShift

пропускается.

В итоговом отчёте эти этапы получают статус:

ПРОПУСК

Это позволяет использовать скрипт даже на устройствах с недостаточным объёмом Flash, не превращая нехватку места в причину полного прекращения установки.

Порог в 50 MB относится к общему объёму /overlay, а не к свободному месту. Фактически доступное место зависит от конкретной сборки OpenWrt и уже установленных пакетов.

⸻

📦 7. sing-box-extended

Скрипт использует фиксированную версию:

v1.14.0-extended-2.7.1

Версия намеренно закреплена и не заменяется автоматически на последний релиз GitHub.

Это сделано для использования конкретного проверенного extended-билда, необходимого для конфигураций NetShift, использующих возможности sing-box-extended.

Автоматическое определение архитектуры

Скрипт не скачивает один и тот же пакет для всех устройств.

Он:

1. читает /etc/openwrt_release;
2. получает DISTRIB_ARCH;
3. определяет пакетный менеджер;
4. получает пакетную архитектуру как резервное значение;
5. определяет формат пакета;
6. ищет соответствующий файл в релизе sing-box-extended.

Используется логика:

DISTRIB_ARCH → PKG_ARCH → RELEASE_ARCH

Поэтому пакет выбирается непосредственно под архитектуру конкретного OpenWrt.

Например, для:

aarch64_cortex-a53

скрипт ищет соответствующий пакет:

_openwrt_aarch64_cortex-a53.apk

при использовании apk.

Для opkg аналогично выбирается соответствующий .ipk.

Поддерживаемые форматы

Для apk:

.apk

Для opkg:

.ipk

Скрипт получает список файлов непосредственно из GitHub Release API и выбирает подходящий пакет по архитектуре и формату.

⸻

🌐 8. NetShift

NetShift обрабатывается после sing-box-extended.

Перед запуском установщика проверяется наличие:

netshift
luci-app-netshift
luci-i18n-netshift-ru

Для каждого пакета определяется:

* установлен ли он;
* требуется ли ему обновление.

Если все три компонента уже установлены и актуальны, повторная установка NetShift не выполняется.

Если хотя бы один компонент отсутствует или требует обновления, запускается установщик NetShift.

Скрипт автоматически скачивает установщик с:

https://raw.githubusercontent.com/yandexru45/netshift/refs/heads/main/install.sh

Файл временно сохраняется в:

/tmp/wrt-aio/

После скачивания скрипт автоматически передаёт установщику необходимые ответы:

2
y

То есть ручное прохождение этих вопросов во время AIO-установки не требуется.

⸻

🧩 9. Работа с временными файлами

Все временные файлы AIO-скрипта хранятся в:

/tmp/wrt-aio

После завершения работы скрипта каталог удаляется автоматически.

Для очистки используется trap, поэтому временные файлы AIO удаляются также при завершении скрипта после выполнения основных операций.

⸻

⏰ 10. Ежедневная перезагрузка

Скрипт проверяет системный Cron:

/etc/crontabs/root

и добавляет:

0 5 * * * /sbin/reboot

Таким образом, роутер автоматически перезагружается каждый день в:

05:00

Если такая строка уже присутствует, второй раз она не добавляется.

После изменения Cron скрипт включает и перезапускает службу:

/etc/init.d/cron

⸻

🔄 11. Автоматическое обновление пакетов

Для систем, использующих apk, скрипт дополнительно создаёт задачу:

0 */5 * * * apk update && apk upgrade

Она выполняется один раз в пять часов.

То есть запуск происходит в:

00:00
05:00
10:00
15:00
20:00

и так далее.

Если такая задача уже существует, дубликат не добавляется.

Для систем с opkg эта задача не создаётся.

Автоматическое обновление через Cron относится именно к apk. Основной AIO-скрипт при этом поддерживает оба пакетных менеджера — apk и opkg.

⸻

🔁 Повторный запуск

OAIOUS рассчитан на повторное выполнение.

При повторном запуске скрипт не просто безусловно устанавливает всё заново, а проверяет состояние компонентов.

Проверяется:

* наличие русской локализации;
* наличие доступных обновлений локализации;
* текущий часовой пояс;
* состояние sysntpd;
* Flow Offloading;
* Packet Steering;
* Steering Flows;
* наличие sing-box-extended;
* наличие и актуальность компонентов NetShift;
* наличие Cron-задач.

Уже существующие корректные настройки повторно не дублируются.

⸻

🌐 Загрузка файлов

Для скачивания файлов используется wget, а при его отсутствии — curl.

Скрипт сначала выполняет обычное HTTPS-подключение.

Если оно не проходит, предусмотрен повторный вариант с отключением проверки сертификата:

--no-check-certificate

для wget либо:

-k

для curl.

Скачанный файл дополнительно проверяется на существование и ненулевой размер.

⸻

📋 Требования

Для запуска необходимы:

* роутер с OpenWrt;
* SSH-доступ;
* права root;
* рабочее интернет-соединение;
* пакетный менеджер apk или opkg.

Для установки sing-box-extended и NetShift необходим общий объём /overlay не менее:

50 MB

Если этот порог не выполняется, скрипт не прекращает работу, а пропускает только требующие дополнительного места компоненты.

⸻

⚠️ Перед установкой

OAIOUS предназначен для автоматизации базовой подготовки OpenWrt.

Перед запуском следует учитывать уже существующую конфигурацию роутера, особенно если на нём настроены:

* DNS;
* DoH;
* DoT;
* VPN;
* Proxy;
* Firewall;
* собственные правила маршрутизации;
* sing-box;
* NetShift;
* другие сетевые сервисы.

Скрипт изменяет системные настройки OpenWrt, поэтому для уже настроенного роутера рекомендуется иметь резервную копию конфигурации.

⸻

🛠 После установки

AIO-скрипт выполняет подготовительную работу, но не пытается полностью настроить роутер под конкретного пользователя.

После завершения необходимо самостоятельно настроить:

* беспроводные сети;
* SSID и пароли Wi-Fi;
* параметры Wi-Fi;
* дополнительные сетевые параметры;
* NetShift;
* подписки NetShift;
* конфигурацию sing-box;
* правила маршрутизации и другие пользовательские параметры.
